# Project status

**Project:** Nexora, a project management and team collaboration app  
**Status date:** 23 November 2026

## What is built

### Product experience

- A branded marketing site with product overview, feature sections, a product showcase, and sign-up/sign-in calls to action.
- Authentication pages for registration, login, email verification, forgot password, and password reset.
- Onboarding and workspace selection screens, including create-workspace flow.
- A workspace dashboard shell with navigation and workspace switching.
- Project screens for portfolio/overview, project details, settings, and a Kanban-style board.
- Task detail drawer UI with status, priority, assignee, due date, description, subtasks, labels, attachments, comments, and activity views.
- Workspace member, invitation, and notification screens.
- Shared UI components and styling for buttons, cards, fields, avatars, dropdowns, skeletons, and icons.

### Working server-backed features

- User registration and login, email verification and resend, password reset by email code, password change, and logout.
- Session listing, revoking an individual session, and logging out all sessions.
- Workspace creation, listing, detail retrieval, updates, and deletion.
- Workspace access checks and role restrictions: owners/admins can update workspaces; only owners can delete them.
- Project creation, paginated listing, project details, updates, and permanent deletion under a workspace.
- Project endpoints require authentication and workspace membership. Workspace members can view, create, and update projects; owners/admins can delete them.
- Project list search, lifecycle filtering, sorting, and creator names, with workspace-wide status totals.
- Project overview, details, create form, settings, and delete action connected to the project API.
- The project board loads its project metadata from the API and shows a clear task-data placeholder until task endpoints are implemented.
- Client API hooks for authentication and workspaces, using React Query.
- Project queries use workspace-scoped React Query keys; create/update/delete mutations invalidate the affected workspace project cache.
- PostgreSQL/Drizzle schema definitions for users, sessions, workspaces and memberships, invitations, projects, tasks, statuses, labels, comments, attachments, activity logs, and notifications.

The live PostgreSQL `projects` table was checked against the project schema and migration. Its key, workspace and creator foreign keys, date check, nullable fields, defaults, and indexes match. All three recorded Drizzle migration hashes match the migration files in the repository. Project deletion is permanent; task records and their dependent rows are removed in a transaction, along with related project/task activity and notification records.

### Project schema details

- Required fields: UUID `id` primary key (generated by PostgreSQL), `workspaceId`, `name` (up to 150 characters), `createdBy`, lifecycle `status`, and `createdAt`/`updatedAt` timestamps.
- Optional nullable fields: `description`, `startDate`, and `dueDate`.
- `workspaceId` references `workspaces.id` with `ON DELETE CASCADE`; `createdBy` references `users.id` with `ON DELETE RESTRICT`.
- Lifecycle values are `ACTIVE`, `ON_HOLD`, `COMPLETED`, and `ARCHIVED`; the database defaults new records to `ACTIVE`.
- A database check prevents a due date earlier than the start date. There is no project slug or unique-name constraint, so duplicate names are allowed within a workspace.
- Indexes include the primary key, unique `(workspace_id, id)` tenant candidate key, `(workspace_id, status)`, and `created_by`.

## Current prototype areas

Several project-management screens remain prototypes backed by local sample data. The workspace dashboard, task details, members, invitation lists, and notifications are not yet loaded from or saved to the server. The project board now loads its project record but has no task columns or cards because task and project-status APIs are not implemented. Project task counts, contributors, and activity also remain unconnected, so the overview/details pages show project records and clearly indicate where task data is not available yet.

The server currently exposes authentication, workspace, and project routes. Although database schemas exist for tasks, comments, invitations, and related data, their APIs and persistence flows are not implemented yet. Invitation acceptance and sending, file storage, and live activity/notification delivery are also not connected end to end.

## Technology

- **Client:** Next.js App Router, React, TypeScript, Tailwind CSS, React Query, Zod.
- **Server:** Express, TypeScript, PostgreSQL, Drizzle ORM, Argon2, JWT/session cookies, Nodemailer.
